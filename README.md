# zeta Markdown Studio

zeta用のチャット本文・キャラクター紹介文を、ブロックで組み立てる日本語Markdownエディターです。スマートフォンを優先したダークUIで、PCでは編集と出力を左右に表示します。

HTML・CSS・JavaScriptを `index.html` に集約しています。フレームワーク、外部ライブラリ、外部フォント、API、データベース、ビルド環境は不要です。アプリから外部への通信は行いません。

## 主な機能

- チャットとキャラクター紹介を独立して編集
- ブロック追加・削除・複製・上下移動、移動後のフォーカス維持
- チャット：セリフ、行動描写、心理描写、情景描写、見出し、区切り線、自由入力
- 紹介文：タイトル、見出し、本文、強調文、引用、箇条書き、番号付きリスト、区切り線、自由入力
- セリフの括弧付与／そのまま／太字、見出しH1〜H3、4種類の強調装飾
- リアルタイムの装飾プレビューと選択可能なMarkdownソース
- Markdown全文コピー、従来方式へのフォールバック、手動コピー案内
- localStorageへの自動保存・復元、JSON入出力、確認付き初期化
- チャット3種・紹介文2種のテンプレート。末尾への追加／置き換えを選択
- 通常ブロックのMarkdownエスケープ設定、自由入力はMarkdownを保持

## 使用方法

1. 「チャット作成」または「キャラクター紹介文」を選びます。
2. ブロックに入力します。「＋ ブロックを追加」で種類を選んで追加できます。
3. 各ブロックの矢印・複製・削除ボタンで構成を整えます。
4. 装飾プレビューとMarkdownソースで確認します。
5. 画面下の「Markdownをコピー」を押し、zetaに貼り付けます。

設定・データ管理からエスケープ切り替え、JSONの書き出し・読み込み、初期化ができます。JSON読み込みと初期化は**両モードとアプリ設定**を対象にするため、実行前に確認が表示されます。テンプレートは現在のモードだけに適用されます。

## GitHub Pagesでの公開

1. この変更を `main` にマージします。
2. リポジトリの **Settings → Pages** を開きます。
3. **Build and deployment → Source** を **Deploy from a branch** にします。
4. ブランチ `main`、フォルダー `/ (root)` を選んで **Save** を押します。
5. デプロイ完了後、Pages画面の公開URLを開きます。

想定URL：<https://yuyuyu855.github.io/zeta-markdown-studio/>

静的ファイルのみで動作し、ルート絶対パスやビルド処理を使用しないため、GitHub Pagesのサブパスに対応します。公開前に、個人のチャット内容、エクスポートJSON、ブラウザ保存データがコミットに含まれていないことを確認してください。初期ブロックの内容は空です。サンプルの文章は入力欄のプレースホルダーです。

## ローカルでの起動

`index.html` をブラウザで開けます。ただし `file://` でのlocalStorageやクリップボードの利用可否はブラウザによって異なります。安定した動作確認には、任意でローカルHTTPサーバーを使います。

```sh
python3 -m http.server 8000
```

<http://localhost:8000> を開いてください。アプリ自体にPythonやNode.jsは不要です。Clipboard APIはHTTPSまたはlocalhostで利用します。失敗時は従来方式を試し、それでも失敗するとソース全文を選択して手動コピーを案内します。

## データ保存仕様

- 保存先：使用中のブラウザ・オリジンのlocalStorage。キーは `zeta-markdown-studio`。
- 保存内容：`version: 1`、現在のモード、両モードのブロック配列と各設定、エスケープ設定。
- テキストの入力・設定変更・ブロック操作時に自動保存します。
- 端末・ブラウザ・オリジン間では共有されません。ブラウザデータ削除やプライベートブラウズ終了で失われる場合があります。大切な文章はJSONでバックアップしてください。
- 容量超過やアクセス拒否時は保存エラーを表示し、メモリ上の編集は継続できます。
- 保存データ破損や未対応バージョンでは空の画面で起動し、元の保存値を上書きしません。JSON読み込みまたは初期化で保存を再開できます。読み込めなかった文章は画面には復元されません。
- JSON読み込みは構造・モード・ブロック種類・設定値を検証し、未知フィールドを除去します。各モード500ブロック、各テキスト100,000文字、読み込みファイル5MBが上限です。大容量の書き出しは5MB以内か確認してください。
- JSONには両モードの文章が含まれます。公開リポジトリに置かないでください。

## Markdown・zeta互換性

**zetaでの実際の表示は未検証です。完全対応を保証しません。** 装飾プレビューは一般的なMarkdownの参考表示です。設定内と `SYNTAX_SUPPORT` に、基本構文とzetaで検証が必要な項目を分けて管理しています。実際の検証結果が得られたら、この設定オブジェクトを更新できます。

プレビューは太字、斜体、太字＋斜体、打ち消し線、H1〜H3、リスト、引用、区切り線、インラインコードに対応する簡易レンダラーです。CommonMark全体の実装ではありません。ネストしたリスト、リンク、画像、表、コードフェンスなどの完全な描画は対象外です。自由入力のソースは保持するため、Markdownソースでも確認してください。

通常ブロックでは意図しないMarkdown構文を防ぐため記号をエスケープします。zetaで表示が崩れる場合は設定をオフにしてください。日本語・全角記号・内部の改行は保持し、ブロック境界の余分な改行を除去して1空行で結合します。複数行の斜体・強調は各行を個別に装飾します。見出しは最初の行に見出し記号を付けます。リストの空行は空項目として出力しません。

ユーザーの入力はDOM API・テキストノードで描画します。HTML、JavaScript、イベント属性は実行しません。`innerHTML`・`eval`・外部Markdownパーサーは使用していません。

## テスト

本体の実行時依存はありません。テストは開発時だけ利用します。

```sh
node tests/core.test.cjs
```

Markdown生成、括弧の重複防止、各装飾、順序、空入力、改行、日本語、記号、保存形式検証を7テストで確認します。

ブラウザ回帰テストにはNode.js、Playwright、Chromiumが必要です。Playwrightを別途利用可能にし、HTTPサーバーを起動してから実行します。

```sh
python3 -m http.server 4173
# 別のターミナルで
node tests/browser.cjs
```

`TEST_URL` で接続先、`CHROMIUM_PATH` でChromiumのパス（既定 `/usr/bin/chromium`）を変更できます。テストは接続先オリジンの保存データを変更するため、開発用環境で実行してください。

今回実施済み：

- Node.jsで7テスト成功
- 実Chromiumで追加・削除・複製・移動・モード切り替え・リアルタイム更新・再読み込み復元
- テンプレートのキャンセル・追加・置換、JSON書き出し／読み込み、不正JSON・不正ブロック拒否
- HTML／script／イベント属性の不活性、プレビューの見出し・リスト・引用描画
- コピー成功・従来方式・手動コピー案内（APIをスタブ化して各分岐を検証）
- 320、375、768、1280pxで横方向のはみ出しなし
- 初期化の確認、保存破損時の上書き防止、ストレージ容量超過時の表示
- モバイル幅とPC幅のスクリーンショットによる目視確認

未実施：実iPhone／Androidのタッチ・ソフトウェアキーボード、Safari／Edge、実OSのクリップボードとの連携、スクリーンリーダー、zetaへの貼り付け表示、GitHub Pages本番配信。これらは公開後の受け入れ確認が必要です。
